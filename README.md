# 星迹 — iCloud 照片空间

一个原生 macOS 照片浏览器，通过系统 PhotoKit 读取这台 Mac 已同步的 iCloud 照片，并以星云、层叠、轨道和画廊四种空间方式呈现。

| | |
|---|---|
| **当前版本** | v1.1（构建号 2） |
| **发布日期** | 2026-10-13 |
| **系统要求** | macOS 15 或更高 |
| **架构** | 通用二进制（Apple Silicon + Intel） |
| **依赖** | 无第三方依赖 |

想直接使用请跳到[下载安装](#下载安装)；想看这一版改了什么请跳到[更新日志](#更新日志)。

## 功能

- 星云：滚轮或纵向拖拽沿拍摄时间穿越；移动指针改变视角，捏合控制镜头距离，前后景自动虚化。
- 层叠：按主题聚成独立卡组，未识别照片单独成组；点击卡组展开为组内 CoverFlow，支持滚轮、拖拽、翻页按钮和位置滑块。点击中央照片查看高清大图，返回时收回卡组。
- 日期：所有模式左下角显示当前照片的年月日；悬停照片时优先显示这张照片的日期。
- 苹果相册：层叠默认直接沿用 PhotoKit 提供的用户相册、收藏、自拍、人像模式、实况、全景、截图、长曝光和 RAW 分组。同一照片可出现在多个相册中；未覆盖照片单列，仍排除视频。“自动主题”保留为独立选项。该功能不等于读取苹果相册内部的场景搜索或人物与宠物识别结果。
- 轨道：滚轮或拖拽旋转照片环；移动指针改变轨道纵深，捏合在近景弧线与完整圆环之间缩放。
- 画廊：全量网格懒加载；滚动浏览、悬停倾斜，捏合调整网格密度。
- 背景：右上角太阳/月亮按钮在黑色与白色背景之间切换，照片本身保持原色。
- 清晰度：默认关闭景深虚化；光圈按钮可开启轻微远景虚化。放大卡片按实际显示尺寸请求高清图片，尺寸升级时保留原有预览。
- 快速跳转：星云、层叠和轨道右下角提供上一张、下一张和位置滑块，可以快速抵达全图库中的任意位置。
- 简洁界面：纯色黑白背景，年份和主题收进菜单；移除方格、渐变、照片角标、重复计数和装饰说明。
- 流畅性：星云只绘制附近 36 张、轨道 20 张、层叠 21 张（图库索引仍完整）；输入按 60 Hz 合并，固定高清加载档位，识别结果批量更新。星云远处淡入、近处淡出，图片加载完成后短暂渐显。
- 全量索引：不再限制 360 张；读取图库中的所有静态照片与实况照片，自动排除视频。缩略图只在进入屏幕时按需读取。
- 智能主题：在本机依次识别全部照片中的演出现场、美食、人物、风景、宠物、城市、旅行和文档；使用精确场景标签与清晰图片，只有证据充分且领先其他主题时才分组，不确定结果放入“待确认”。不再把同一时间段的主题扩散给其他照片。系统标记的截图归入文档。
- 手动修正：打开单张照片后可修改主题，结果保存在本机并优先于自动识别。
- 事件卡组：层叠的分组菜单提供“事件”。跨日期、相邻照片间隔超过两小时或定位相距超过五公里时拆组；没有日期的照片单列。右键卡组可在本机重命名。
- 位置同步：四种模式共享当前照片，分别保留缩放状态。筛选排除当前照片时选择拍摄时间最近的结果；悬停不会改变保存位置。
- 实况照片：先点击进入大图，再长按超过 350 毫秒静音播放，松开、拖动或离开窗口即停止；四种浏览模式的缩略卡片不再注册实况长按手势。下载失败时保留封面，可重新长按重试。
- 大图加载：打开时立即显示已有缩略预览，高清图在后台解码后短暂淡入；关闭大图取消未完成的读取。布局与浏览模式视觉效果保持不变。
- 星云专项减负：相机运动与静态卡片内容分离，缓存不变的卡片视图；悬停日期独立更新。使用 PhotoKit 对邻近照片做有界、本机预热，离开星云即停止，不提前下载 iCloud 原图。原有 36 张可见卡片、弹簧动画参数、穿越路径、缩放、透明度和景深计算保持不变。

## 下载安装

不想自己编译的话，直接下载打包好的版本：

**https://github.com/Justinchengpepe/star-trail/releases/latest**

| 文件 | 说明 |
|---|---|
| `XingJi-1.1.zip` | 通用二进制，同时支持 Apple Silicon（M 系列）和 Intel 的 Mac |

解压后把 `星迹.app` 拖进「应用程序」文件夹即可。要求 **macOS 15 或更高版本**。

### 校验下载包

```sh
shasum -a 256 XingJi-1.1.zip
```

应得到：

```
493cae59bbea8f4b39dc37d52466be9522b2e733286a7b0ea06c6d817a929da4
```

### 首次打开被拦下

> **首次打开会被 macOS 拦下**，提示「无法打开，因为 Apple 无法检查其是否包含恶意软件」。
> 当前公开的 v1.1 是 ad-hoc 签名，没有经 Developer ID 身份认证和 Apple 公证。签名完整性通过不等于应用安全。
> 不建议清除下载隔离标记或绕过 Gatekeeper 警告。正式签名、公证版本尚未发布；不要向未经验证的下载包授权私人相册。

如果确认来源可信，用系统提供的方式打开：**右键点击 `星迹.app` → 选「打开」→ 在弹窗里再点一次「打开」**。这只对该应用生效一次，之后可正常双击。

## 使用

1. 确保 macOS「照片」App 已开启 iCloud 照片同步。
2. 打开 `星迹.app`（下载版在「应用程序」里，自己编译的在 `dist/`）。
3. 首次运行时点击「允许访问照片」，在系统弹窗中授权。

应用不会上传照片。iCloud 中尚未下载的缩略图或原图，会由 macOS 照片服务按需下载。

主题识别使用 macOS Vision，在本机逐张处理。它可以识别演出场景、食物和画面文字，但不会仅凭人脸自动确认具体歌手姓名；如果舞台屏幕包含姓名，可通过顶部搜索框搜索识别出的文字。照片很多时可随时点击停止按钮，已完成的结果会保留。

识别缓存升级到 v4：只保存主题和置信度，不保存标签或原始 OCR 文字。首次启动会迁移旧缓存并移除旧偏好键，手动分类保留。文字搜索仅使用当前运行期间的识别结果；重启后需要重新识别。系统备份里的历史副本不受迁移影响。

本版要求 macOS 15 或更高版本。新增功能只保留事件卡组、跨模式位置同步和长按实况播放。照片不再进行相似收叠，也不提供自然语言语义搜索；原有日期、主题和识别文字搜索保持可用。

事件索引和事件名称存储在 `~/Library/Application Support/NebulaPhotos/photo-index.sqlite`。事件分组只读取拍摄日期和定位，在后台生成，不再运行相似度比较、向量生成或语义模型推理。旧版生成的模型和分析缓存不再加载；原始照片与手动主题修正保持不变。

### 常用操作

| 想做的事 | 怎么做 |
|---|---|
| 切换浏览模式 | 底部中间的「星云 / 层叠 / 轨道 / 画廊」按钮 |
| 在星云里沿时间穿越 | 滚轮，或按住上下拖拽 |
| 在轨道里旋转照片环 | 滚轮，或左右拖拽 |
| 缩放镜头 | 触控板双指捏合 |
| 跳到任意位置 | 右下角位置滑块，或左右翻页按钮 |
| 打开大图 | 点击任意照片卡片 |
| 播放实况照片 | 先点开大图，再长按超过 350 毫秒 |
| 筛选年份 / 主题 | 底部左侧的两个菜单 |
| 搜索日期、主题、识别文字 | 顶部搜索框（文字搜索需本次运行已识别过） |
| 切换黑白背景 | 右上角太阳 / 月亮按钮 |
| 开关景深虚化 | 右上角光圈按钮 |
| 识别全部照片主题 | 右上角魔法棒按钮，可随时停止 |
| 清除本机分析数据 | 菜单栏「星迹」→「删除全部分析数据…」 |

## 更新日志

### v1.1 — 2026-10-13

**新增**

- 「星迹」菜单增加「删除全部分析数据…」：确认后清除主题、手动分类、识别文字、事件名称、SQLite 索引记录和图片内存缓存，不修改苹果相册；可用同菜单的「重新建立事件索引」恢复。
- 大图打开时立即显示已有缩略预览，高清图在后台解码后淡入，关闭时取消未完成的读取。
- 星云模式引入卡片视图缓存与 PhotoKit 邻近预热：有界、本机执行，离开星云即停止，不提前下载 iCloud 原图。

**改进**

- 照片点击命中与拖动判定：按下时鼠标视差不再把照片移开。
- 图片改为后台解码，过期任务自动取消，刷新按批处理。
- 主题缓存升级到 v4，只持久化主题和置信度；Vision 标签与原始 OCR 文字仅保留在当前进程内存。
- 授权范围变化时剔除失效的主题记录和事件名称；撤权时取消分析、详情请求和实况播放，并清空浏览状态。
- SQLite 清理执行 `secure_delete`、`VACUUM` 和 WAL 截断；清理代际阻止旧后台任务回写。
- 本地构建开启 Hardened Runtime，并保留下载隔离标记；可通过 `STARTRAIL_SIGNING_IDENTITY` 指定已有的 Developer ID Application 证书。

**修复**

- 大图高清加载完成后与缩略预览重叠显示的问题。
- 移除 README 中建议用 `xattr -cr` 绕过 Gatekeeper 的说明。

**说明**

- 首次启动会迁移 v2/v3 旧缓存，移除其中的 OCR 文字副本，保留主题与手动分类；不会恢复旧 OCR，也不声称清除了系统备份中的历史副本。
- 事件名称、主题等派生数据仍以明文存放在本机，本次未实现加密数据库。
- 尚未取得可靠的 FPS 对比数据，因此不宣称掉帧问题已完全修复。

- 提供 arm64 + x86_64 通用二进制。

## 系统要求与依赖

### 运行

- **macOS 15** 或更高版本
- Apple Silicon 或 Intel 处理器（通用二进制）
- 需要在 macOS「照片」App 中开启 iCloud 照片同步

### 从源码构建

- macOS 15 自带的 Swift 命令行工具：`swiftc`、`lipo`、`iconutil`、`codesign`
- **零第三方依赖**，不需要 Xcode 工程文件或包管理器
- 可选：设置 `STARTRAIL_SIGNING_IDENTITY` 环境变量，用已有的 Developer ID Application 证书签名

## 从源码构建

在项目目录运行：

```sh
chmod +x build.sh
./build.sh
```

只需要 macOS 自带的 Swift 命令行工具，不依赖第三方库。脚本会分别编译 arm64 与 x86_64，再用 `lipo` 合成通用二进制，产物在 `dist/星迹.app`。

## 兼容性与已知限制

- **签名与公证**：默认仍是 ad-hoc 签名、未公证、未启用 App Sandbox。Hardened Runtime 和签名完整性校验不等于安全认证。正式签名与公证版本尚未发布。
- **沙箱**：尚未启用。启用前需要验证 PhotoKit / iCloud 下载、偏好与数据库的容器迁移，再制定最小权限配置。
- **TCC 撤权**：应用会在刷新时重新读取权限并清理状态，但系统层撤权场景尚未在隔离账户中实测。
- **网络行为**：图像分类和 OCR 使用本机 Vision，应用没有照片上传接口；但 PhotoKit 允许系统按需下载 iCloud 内容，未做运行时抓包，不能据此保证「绝对不外传」。
- **文字搜索**：仅使用当前运行期间的识别结果，重启后需要重新识别。
- **不提供的功能**：照片相似收叠、自然语言语义搜索。日期、主题和识别文字搜索保持可用。
- **数据清理范围**：只针对应用派生数据。系统备份、旧发布 ZIP、旧应用副本中的历史内容不在清理范围内。
- **本地数据**：事件名称、主题等派生数据以明文存储，尚未加密。

## 本机数据与发布防护

- “星迹”菜单提供“删除全部分析数据…”：确认后清除主题、OCR 内存结果、手动分类、事件命名、所有 SQLite 索引记录及图片内存缓存，不修改苹果相册。SQLite 使用 secure_delete、VACUUM 和 WAL 截断；这不是物理介质或备份的取证级擦除保证。事件索引暂停生成，可用同菜单的“重新建立事件索引”恢复。
- 刷新时重新检查照片权限，剔除不再授权的主题记录及事件名称。撤权时取消分析、详情请求和实况，关闭详情并清空浏览数据；系统行为仍需在隔离账户中验证，不宣称绕过或替代 TCC。
- 图像分类和 OCR 使用本机 Vision。应用没有照片上传接口；PhotoKit 允许系统按需下载 iCloud 内容，并不代表应用禁止一切联网。未做运行时抓包，不能据此保证“绝对不外传”。
- 本地构建开启 Hardened Runtime；默认仍是 ad-hoc 签名、未公证、未沙箱化。可通过 `STARTRAIL_SIGNING_IDENTITY` 指定已有 Developer ID Application 证书；正式公证还需账户凭据、上传和校验。沙箱迁移及 iCloud 下载兼容性尚待验证，不将其标为已完成。
- 发布前记录源码提交和最终包 SHA-256，并在隔离账户用虚构照片验证浏览、识别、实况、清理和撤权。旧公开 v1.0 包不会因本地源码修改自动更新。

交互研究参考：[Carousel.SwiftUI](https://github.com/JuniperPhoton/Carousel.SwiftUI) 的连续位置控制和 [CoverFlow 示例](https://gist.github.com/Codelaby/3d80c1e475bf036399d97ee8eb5861be) 的空间卡片效果；实现保留原生 SwiftUI，不引入额外依赖。
